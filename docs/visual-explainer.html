the whole design

Four facts — and that is all of it.

01

One lesson, one line

At most 200 characters. Not a document — a single hard-won reminder you could read aloud.

02

Voted, not aged

+1 when a lesson helped, −1 when it misled. Good lessons float up; no decay curve, no scheduler.

03

Bounded, and configurable

A small capped list — keep it tight (around 50 lines is plenty; the cap is one setting you tune). When full, the lowest-scored line is evicted, so it self-cleans and never rots into a junk drawer.

04

Plain text

One file per role. You can cat it, grep it, and git diff it. You cannot do that to a vector database.

the counter-intuitive part

Surfaced to the agent — not searched.

The most valuable lesson is the one the agent would never think to search for: the trap it forgot exists. A search only returns what you can already name. So the notebook is surfaced instead — and surfacing is more than dumping a file in front of the agent. Each notebook carries a plain-language description of when to open it, and signals from real use — which lessons get used, which get used together — are mined offline to keep notebooks well-described and well-organized. So when the agent opens one, it meets the lessons relevant to the task, including the ones it didn't know it would need.

A search engine · pull

The agent must ask the right question to get an answer back. If it forgot the trap exists, it never asks — so the lesson never surfaces.

A notebook · push

The relevant notebook is put in front of the agent — chosen by its description, organized by how its lessons are actually used — so the forgotten lesson arrives unasked. That's the serendipity other tools miss.

the rhythm of a task

Four small moments.

Read

At task start, the notebook is shown so the agent begins informed. nb show

Consult

Mid-task, check if a past job already covers this. nb list

Delegate

A helper agent gets its own notebook for its own role.

Retrospect

At the end, vote on what helped, add one new lesson. nb vote

Moment four is where it compounds: a thumbs-up to the notes that helped, a thumbs-down to any that misled, and the single most useful new thing learned — one line. Do it after every task and the notebook quietly gets smarter on its own.

built for both readers

For the human, and for the agent.

If you are a person

You can read exactly what your assistant "believes," correct a wrong line by deleting it, and watch memory form over time in git. The memory is as transparent and editable as a to-do list.

If you are an agent

Read your role's notebook before you plan; vote the lessons that helped and prune the ones that misled; add at most one new ≤200-char lesson at task end. Never pad — "nothing new worth storing" is a valid outcome.

Is it the right tool?

Yes, for remembering a modest set of durable, hard-won lessons across sessions — and wanting to see and edit that memory. No, for recalling facts across thousands of documents; that is genuine large-scale retrieval — use a real vector store. This does one small thing well, on purpose.
